# 光圈科技实验室官网 · 开发与交付

版本：v5 / 2026-10-11。交付方式：完成修改与检查后，打包发送给负责人。网站没有上传入口、部署后台、登录或自动发布服务；打包不修改线上网站。

## 页面功能与访问路径

首页以项目、成员与资料为主。首屏提供项目目录、成员墙及资料入口，保留品牌光圈；原大型招新口号、招募 FAQ 和 LET’S MAKE 区块已移除。联系方式放在独立联系页。

项目目录支持关键词搜索与方向筛选，显示项目状态、技术标签和维护入口。当前仅列入真实存在的实验室官网项目，不编造其他作品。`content/projects.json` 是项目数据来源；`scripts/projects.cjs` 校验并生成卡片，`public/assets/projects.js` 负责筛选。无 JavaScript 时仍能阅读全部项目。

成员墙保留六个无名空白展示位；录入真实资料后才启用成员搜索和筛选。资料区提供站内 `/docs/` 开发文档和两个可下载模板：项目提案、开发提交清单。协作区分别引导提出项目、维护官网、交流加入。

官网文档通过 `src/docs.template.html` 维护，由构建脚本输出 `public/docs/index.html`；不需要 JavaScript 即可阅读和使用目录。`public/assets/portal.css` 管理重构后的首页及文档布局。

## 项目数据格式

`content/projects.json` 为数组。每条包含：唯一 `id`（小写字母、数字、短横线）、`title`、`summary`、`direction`、`status`、字符串数组 `tags`、链接数组 `links`。

方向为 `software`、`hardware`、`systems`；状态为 `developing`（开发中）、`maintaining`（持续维护）、`archived`（已归档）。每个链接含 `label` 和 `url`；URL 支持 HTTPS、本站目录路径或页内锚点。校验失败时构建会停止。项目为空时显示明确的空状态，不自动生成示例成果。

下载资料位于 `public/downloads/`；新增后应同时更新首页资源入口。项目与成员数据最终渲染进静态 HTML，浏览器不会请求后台数据库。

## 运行环境与命令

使用 Node.js 22.13 或更新版本（已在 22.23.2 检查），Windows PowerShell 用于打包。页面运行不依赖外部字体、CDN 库或服务器 API。构建只使用 Node 内置模块；图标回归测试使用开发依赖 sharp。

```powershell
npm ci
npm run build
npm run check
npm test
npm run dev
```

打开 http://127.0.0.1:8765 。不要直接双击 HTML：ES modules 应通过本地 HTTP 服务加载。Ctrl+C 停止预览。`npm run dev` 不自动构建，修改模板或成员数据后需再次执行 `npm run build`，再刷新浏览器。

## 维护成员墙

当前数据：

```json
{"placeholderCount": 6, "members": []}
```

`placeholderCount` 为 0–12 的整数，只在 `members` 为空时生效。真实成员存在时不混入虚构占位人员。方向枚举为 `software`、`hardware`、`systems`，分别对应软件与人工智能、机器人与电子制作、网络与系统。

每条成员数据支持：

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| `id` | 是 | 唯一的小写字母、数字、短横线，例如维护者自定的稳定标识 |
| `name` | 是 | 展示姓名或昵称，非空，最多 40 个字符 |
| `directions` | 是 | 上述枚举组成的数组；可为空或多个方向 |
| `role` | 否 | 经确认的职责文字 |
| `bio` | 否 | 简介 |
| `avatar` | 否 | `/assets/members/文件名.webp` 或 `.png`；只允许字母、数字、短横线、下划线文件名 |
| `url` | 否 | HTTPS 个人主页，不允许带用户名密码 |

未提供头像时用姓名首字作简洁占位。头像存入 `public/assets/members/`，建议裁成方图、压缩为 WebP；卡片按 4:3 视窗居中裁切。添加前确认本人同意公开，勿从社团申请表自动公开学号、电话等资料。所有用户文字做 HTML 转义，链接与本地头像路径经过校验。

录入后重新构建。检查成员卡、外链、方向筛选、关键词搜索与无结果提示。搜索不区分英文字母大小写，方向和关键词同时生效；清空搜索并选择“全部”恢复所有卡片。

## 联系方式及二维码

只修改 `site.config.json` 的 `contact`。`qrExpiresAt` 使用含时区的 ISO 时间，例如北京时间使用 `+08:00`；`qrValidityLabel` 是页面可读说明，两者应同步更新。当前二维码截止时间仍为 2026-09-27，已过期，正常联网浏览器会显示联系入口而隐藏码区；没有新二维码，不自行延长有效期。

JavaScript 关闭时仍能看见二维码有效期与联系电话。更换二维码应使用真实原图，保留完整白边，不用生成式图片重绘二维码。

## Logo 与动画维护

页头、页尾保留静态原 Logo；ICO 和 SVG favicon 保持透明背景。八叶动画沿用当前 Logo 派生的固定叶片与固定支点，`iris-animation.js` 统一驱动，支持反向和减少动态效果。它是刚体运动视觉模型，不代表已经验证的制造机构。本次页面重构不改动其几何。

`scripts/logo-leaves.cjs` 生成 `public/assets/logo-leaves.js`；`iris-geometry.js` 定义姿态，`iris-renderer.js` 绘制 Canvas，`scripts/aperture.cjs` 生成无 JavaScript 静态图。需要更新图标资源时执行 `node scripts/make-aperture-assets.cjs`。静态标志来源：https://commons.wikimedia.org/wiki/File:Aperture_Science_Logo.svg 。

## 提交方式：打包发送

```powershell
npm run package
```

脚本先构建、校验内部链接/体积、运行测试，再创建新的时间戳交付目录，不覆盖历史交付。

交付包含：

1. `source.zip`：可编辑源码、当前 `public`、数据、配置、测试、依赖锁文件及开发文档，不含 node_modules。
2. `site.zip`：只含 `public` 内文件，ZIP 根目录直接是 index.html、assets 等，可供负责人手动发布。
3. `开发文档.md`、`交付说明.md`、`校验清单.json`。
4. 外层完整交付 ZIP：将上述内容一并发送给负责人。

只需发送外层 ZIP；每次提交说明修改内容、检查结果和剩余问题。凭据、旧备份、部署历史、无关社团文档不进入交付包。负责人决定是否发布；开发者不在网站内上传 ZIP，不嵌入 API Token，不运行自动部署。

## 人工验收与回退

检查桌面、768px 平板、390px 手机；无横向溢出，首屏文字和图形不重叠。核对导航锚点、窄屏菜单、FAQ、联系方式以及成员墙空白状态。若新增真实成员，再验证筛选、搜索、头像和个人链接。检查控制台无错误。

交付 ZIP 的文件清单含 SHA-256，收件人可用 `Get-FileHash` 比对。修改后保留上一份交付包，需要撤销时恢复上一份源码或由负责人手动发布上一份 `site.zip`。v4 已于 2026-10-11 发布；后续修改仍需经负责人确认发布，不能把本地验收当成线上更新证据。页面轻量化也不代表解决了所有大陆网络访问问题。
